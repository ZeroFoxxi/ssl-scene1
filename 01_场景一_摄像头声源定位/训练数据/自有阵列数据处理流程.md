# 自有阵列数据处理流程（录音 → 微调 → 评测 → 实时 demo）

内部操作说明，不是给 mentor 的材料。采什么、采多少见同目录 `会议室实录采集方案.pptx`。所有命令在 `code/ssl_baseline/` 下运行。

## 0. 先确认

- 阵列几何：麦克风个数、沿阵列的坐标（米，按通道顺序）、采样率（16 kHz 以外会自动重采样）。
- **仿真模型要与阵列几何一致**。如果是 6 麦线阵 17.5 cm，直接用会议室仿真模型（服务器上 `crnn_meeting_60k_s_seed1`，云端 `crnn_v0`）；
  如果几何不同，先在 `scripts/gen_meeting_train_data.py` 的 `ARRAYS` 里加一项，在服务器上用 `ARRAY=<新名字> bash server_kit/start.sh` 训练仿真模型。

## 1. 录音整理成清单

每段录音一个多通道 wav / flac（通道顺序与阵列一致）；建一张 CSV 清单（UTF-8）：

| 列 | 内容 |
|---|---|
| `path` | 录音文件，相对录音根目录 |
| `room` | 房间名（训练、挑选、测试按房间分开） |
| `kind` | `speech`（单人说话，音箱或真人）或 `noise`（无人说话的背景声） |
| `azimuth_deg` | 说话位置相对阵列的方位：正前方 0°，左右 ±90°（线阵前后不分）；`noise` 行留空 |
| 其他列 | `distance_m`、`height_m`、`speaker`、`position` 等，可选，不参与计算 |

说话录音要截好：文件开头即开口、结尾即说完（与 RealMAN 话语文件相同）。

## 2. 生成微调数据与测试集

```bash
python scripts/build_own_finetune.py --manifest <清单.csv> --root <录音根目录> \
    --train-rooms <房间A> --val-rooms <房间B> --name train_data_own_ft
python scripts/build_own_finetune.py --manifest <清单.csv> --root <录音根目录> --test-rooms <房间C> --name own_test
```

- 训练样本总数默认 4,500（按房间平均分）；挑选模型每个房间 400 个；测试每个房间 60 个目标话语 × 换人 / 抢话。
- 做法与 RealMAN 版完全相同（已用 RealMAN 校验：微调数据与测试集都与原脚本输出逐字节一致）。
- RealMAN 上的经验：约 9 分钟录音（每个房间约 3 分钟）微调已与 143 分钟相当，1 个房间也够；约 5 分钟开始下降。

## 3. 微调

```bash
python scripts/finetune_doa_net.py --init work/models/<仿真模型>.pt --name crnn_own_ft \
    --real train_data_own_ft --sim <仿真模型的训练数据，见模型旁 .json 的 data> --steps 1128
```

服务器上加 `--device cuda`。每批一半实录、一半仿真；挑选房间上最好的一轮保存为 `work/models/crnn_own_ft.pt`。

## 4. 评测（测试房间只评测一次）

```bash
python scripts/eval_locata.py --ckpt work/models/crnn_own_ft.pt --data work/own_test/test.npz \
    --mic-x <各麦克风坐标> --out own_eval --tag _ft
```

同时给出 SRP-PHAT、GEVD-MUSIC 与小网络的误差 ≤10°、≤20° 比例与平均误差（`out/own_eval_ft.json`）。微调前的仿真模型也评一次作对照。

## 5. 实时 demo

```bash
python scripts/run_stream_demo.py --wav <一段会议录音> --mic-x <各麦克风坐标> --ckpt work/models/crnn_own_ft.pt --conf 0.7
python scripts/run_stream_demo.py --live --mic-x <各麦克风坐标> --ckpt work/models/crnn_own_ft.pt --conf 0.7 --seconds 120
```

- 输出每 0.1 s 的摄像头朝向、测向方位与置信度（csv + 图），并打印每块处理耗时。
- 流式转向与离线评测逐块一致（`scripts/check_stream_equivalence.py`、单元测试）。
- `--live` 需要 `pip install sounddevice`，**尚未在硬件上测试**；置信度门限 0.7 是在仿真验证会议上选的，自有阵列上需要用挑选房间的录音重新确认。
