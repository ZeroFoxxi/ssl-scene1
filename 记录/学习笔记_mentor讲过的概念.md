## 一、语音交互链条：几个模块是怎么串起来的

mentor 设想的完整链条（11-16）：

```
语音唤醒 → 声源定位 → 波束成形 → ASR（语音识别）→ 理解 / 翻译 → TTS（语音合成）
 "小艺小艺"   人在哪个方向   只听那个方向    声音变文字                 文字变声音
```

| 词 | 一句话 | 打个比方 | 和我们的关系 |
|---|---|---|---|
| **语音唤醒（KWS）** | 设备一直低功耗地听，听到唤醒词才"醒过来" | 叫名字才回头 | mentor 负责；会议室场景一般不需要 |
| **声源定位（SSL / DOA）** | 判断声音从哪个方向来 | 闭着眼听出谁在说话 | **我负责**。DOA 是"到达方向"，是声源定位的核心输出 |
| **波束成形（Beamforming）** | 用多个麦克风，只增强某个方向的声音，压低其他方向 | 把耳朵"对准"一个人 | 需要声源定位告诉它方向；做得快可以延伸做 |
| **ASR** | 语音 → 文字 | 速记员 | 定位和波束成形做好了，ASR 识别率才高 |
| **TTS** | 文字 → 语音 | 播音员 | 另一位同学在做；地图导航播报就是 TTS |
| **声纹识别** | 从声音判断是谁 | 听声音认人 | 智能家居场景后续要加 |
| **音色 / 声音克隆** | 用某人的音色说话 | 模仿秀 | 耳机长期设想之一，很远 |
| **音效渲染** | 让耳机里的声音听起来像从某个方向、某个房间传来 | 3D 环绕声 | 耳机 demo 的另一半；mentor 说现在难度太大，先不做 |

**mentor 可能问**：为什么要先定位再做波束成形？→ 波束成形要知道"对准哪里"，方向就是定位给的。

## 二、"端侧"相关：为什么模型要那么小

| 词 | 一句话 | 和我们的关系 |
|---|---|---|
| **端侧（on-device）** | 算法直接在设备的芯片上跑，不靠服务器 | 我们做的都是端侧 |
| **离线 / 联网（"联云"）** | 离线 = 不上网也能用；联网 = 把声音传到云端服务器算 | 偏向离线：联网成本高；离线还有**隐私保护**的好处（声音不上传） |
| **低功耗** | 设备耗电少 | 端侧设备（耳机、摄像头）电池小，功耗是 mentor 很在意的指标 |
| **参数量** | 模型里需要存的数字有多少个，决定模型多"大" | 端侧模型一般只有**几百 K**（几十万个）；mentor 去年交付的约 500 K；联网大模型动辄几 B（几十亿） |
| **计算量（FLOPs / MACs）** | 模型算一次要做多少次乘加 | 决定耗电和速度；和参数量是两回事 |

**单位换算**（容易搞混）：

| 写法 | 意思 | 例子 |
|---|---|---|
| K | 千（10³） | 500 K 参数 = 50 万个参数 |
| M（"兆"） | 百万（10⁶） | 3 M 参数 = 300 万个参数 |
| B | 十亿（10⁹） | 7 B 大模型 |

- 参数量 → 存储大小：8 比特量化后每个参数占 1 字节，所以 **500 K 参数 ≈ 500 KB**；用 32 位浮点存就是 4 倍，约 2 MB。

**mentor 可能问**：为什么不直接用大模型？→ 端侧放不下、成本高；"做一二十 M 的端侧模型，还不如直接联网"。

---

### "端侧"和"神经网络"不是一回事

| 概念 | 意思 |
|---|---|
| **端侧** | 算法在**哪里**跑：设备自己的芯片上，不靠云端 |
| **神经网络（小模型）** | 算法**是什么**：用数据训练出来、有很多参数的模型 |

- 端侧可以跑传统方法（SRP-PHAT、GEVD-MUSIC：公式计算，没有参数，不用训练），也可以跑神经网络（网络必须很小，所以叫"端侧小模型"）。
- **为什么判断声源定位原型是神经网络**：mentor 回答选型问题时讲的是参数量（几百 K）、先大后压、剪枝 / 减通道 / 减层、8 比特量化，这些都只对神经网络有意义；他调研 PPT 的"端侧轻量化"阶段列的也是神经网络。**这是推断，mentor 没有直接说"神经网络"**，周会时顺带确认。
- 比方：传统方法 = 按菜谱做菜（公式人写好）；神经网络 = 学徒看了几万次学会做菜（参数 = 学到的经验）；端侧 = 小厨房，所以学徒的"脑子"要小，需要压缩和量化。

### 传统方法和训练数据的关系

- 传统方法的公式来自物理原理（声速 + 麦克风位置 → 时间差 → 方向），不是从数据学的；换房间公式不变。只有窗口长度、阈值等少数数字靠人工挑（仿真就是在帮着挑）。
- 训练集、验证集只给神经网络用；**测试集两者都要用**，同一套数据上比才公平。
- 用了神经网络，传统方法仍然有用：① 对照基线（网络要比它好）；② 网络的输入特征（IPDnet 用相位差 IPD，Cross3D 用 SRP-PHAT 空间图）；③ 系统里不用学的部分（跟踪、云台状态机）。

## 三、模型规格怎么定（mentor 11-16 讲的方法）

1. **以竞品为标准**：规格和竞品在同一量级。竞品几百 K，你做 3–4 M 就没竞争力。
2. **查不到竞品数字**：按能找到的最小版本定。
3. **先大后小**：开发时先放大约 10 倍（竞品 2 M → 先做 20 M），效果做好了再压缩下来。
   - 原因：竞品也是迭代很多版本、从大压到小的；一开始就做很小的模型，很难把效果做出来。

### 压缩的两条路

| 方法 | 一句话 | 打个比方 |
|---|---|---|
| **剪枝 / 减通道 / 减层** | 把网络里不重要的部分删掉，让网络变"瘦" | 把一本书删掉不重要的章节 |
| **量化** | 把每个数字从高精度（32 位浮点）换成低精度整数（8 位、4 位） | 把"3.14159265"记成"3.14" |

- **8 比特量化（INT8）**：业内通用，存储省到 1/4，效果损失通常可接受。
- **4 比特量化**：再省一半，但直接套用 8 比特的方法效果会差很多，要专门研究——**mentor 自己在研究这个**。
- 压缩一定会让效果下降，目标是"降在可接受范围内"。

**mentor 可能问**：我们的规格目标是多少？→ 目前判断：约 0.5 M 参数、INT8，开发版约 5 M 起步【待确认】。依据是公开的端侧参照：Cross3D-Edge 0.14 M、IPDnet2-Tiny 0.5 M、SELDnet 端侧约 0.85 M。

## 四、方法分类（对照 mentor 调研 PPT《声源定位调研-周学浩-v2》的分类树）

mentor 的分类树按"要回答的问题"由简到难分三类：

| 类别 | 回答什么 | 需要什么 | 和我们的关系 |
|---|---|---|---|
| **① DOA（方向估计）** | 声音从哪个**方向**来（角度 θ） | 1 个麦克风阵列 | **我们做这个**。mentor："后面主要以 DOA 那个方法为主"。摄像头转向只需要方向 |
| ② 2D/3D 坐标定位 | 方向 + **距离**（坐标 x,y,z） | 2 组阵列 + 已知间距，三角测量 | 暂不需要 |
| ③ SELD（事件定位与检测） | 方向 + **是什么声音** + 起止时间（人声、狗叫、警笛同时出现） | 1 个阵列 + 训练好的网络 | 会议室不需要分辨事件类别，不做；除非耳机 demo 找到多种声音同时发生且有价值的场景 |

DOA 内部又分四种做法（mentor PPT 里也有）：

| 做法 | 代表方法 | 一句话 | 打个比方 |
|---|---|---|---|
| 时延类（TDOA） | GCC-PHAT | 两个麦克风谁先听到、差多少时间，反推方向 | 两只耳朵听方向 |
| 波束扫描类 | SRP-PHAT | 把每个候选方向都"试听"一遍，最响的就是 | 拿手电筒一格格扫 |
| 子空间类 | MUSIC / ESPRIT | 先把噪声分离掉，只看和方向有关的规律，峰最尖的方向就是 | 先关掉背景音再听 |
| 深度学习类（DNN） | CNN / CRNN / IPDnet2 / LightDOA | 用神经网络从特征直接学出角度，需要训练数据 | 听多了自然会判断 |

- 我们的基线代码用的是前三种（SRP-PHAT、GEVD-MUSIC）；参数量、量化、训练数据这些讨论都针对第四种。
- **GEVD-MUSIC**：MUSIC 的改进版，先用"说话前那段背景噪声"把噪声"白化"掉再找方向，所以抗固定噪声源（电视、空调）。

## 五、项目类型

| 词 | 一句话 |
|---|---|
| **预研（技术预研）** | 先研究出算法原型和技术方案，不直接交给客户；**也要交付**，有大致时间 |
| **交付型项目** | 直接给客户或产品线，要随时对接；每周来两天的实习生一般不安排 |
| **洞察** | 调研和讨论"这个方向有没有价值、有哪些可能的场景" |
| **demo** | 演示原型。mentor：demo 做好了给领导看，领导感兴趣后才会看技术方案，所以**场景价值最重要** |

## 六、场景相关

| 场景 | 要点 |
|---|---|
| **会议室（场景一的选型场景）** | 一人发言、其他人一般不说话；谁说话摄像头就转向谁；是公认有价值的场景 |
| **家居** | 先唤醒，再定位，再用波束成形压掉其他人的声音（十几个人聚餐时说"小艺小艺"）；更复杂，后续扩展 |
| **耳机 demo** | 要回答"为什么必须戴耳机"。mentor 举例：多人场合面对面翻译——人知道自己在和谁说话，耳机不知道，要靠定位找出交流对象 |

## 六b、连训练服务器时的几个词（11-18 补充）

| 词 | 一句话 | 打个比方 |
|---|---|---|
| **服务器地址（IP）** | 服务器在网络里的位置；10 开头的是公司内网地址，外网访问不到 | 楼的地址 |
| **端口** | 服务器上某个服务的编号；SSH 远程登录默认 22，管理员可能改成别的 | 楼里的房间号 |
| **SSH** | 远程登录服务器、在上面敲命令的方式；VS Code 用 Remote-SSH 插件（发布者须为 Microsoft） | 进房间的门 |
| **跳板机（堡垒机）** | 先登录的一台中转机器，再从它登录训练服务器；便于公司管控和记录访问 | 前台 / 门卫室 |
| **网络权限** | 办公网和服务器网可能隔开，需要申请开通 | 门禁卡 |

- 自查网络通不通（Windows PowerShell）：`Test-NetConnection 服务器地址 -Port 端口`，看 `TcpTestSucceeded` 是 True 还是 False；ping 不通不一定代表连不上（很多服务器屏蔽 ping）。
- 不要自己挨个端口去试（端口扫描），可能触发公司安全告警；端口、跳板机问管理员或 mentor。
- 密码只在登录框里输入，不发给别人、不写进文件。

## 七、训练神经网络时的几个词（11-18 补充）

| 词 | 一句话 | 我们这次 |
|---|---|---|
| **训练集** | 网络用来"学"的数据 | 12,000 个仿真片段 |
| **验证集** | 训练过程中用来检查、挑出最好那一轮模型的数据；网络不从它学 | 1,000 个，房间和人声都和训练集不同 |
| **测试集** | 最后"考试"用的数据，只用一次；不能拿它来调参数，否则成绩会虚高 | 800 个，与传统方法同一批样本 |
| **轮次（epoch）** | 把训练集完整学一遍叫一轮 | 20 轮，每轮约 3.3 分钟 |
| **损失（loss）** | 网络答案和标准答案差多少，越小越好 | 训练中应该不断下降 |
| **过拟合** | 在训练集上很好、换一批没见过的数据就变差（"死记硬背"） | 用验证集挑模型、测试集用没见过的声音，就是为了发现它 |
| **参数量** | 网络里需要存的数字个数 | 276,508（约 0.28 M） |
| **计算量（乘加次数，MACs）** | 网络算一次要做多少次乘法加法，决定在芯片上跑多快、多耗电 | 每次判决约 2.7 亿次 |
| **软标签** | 不只说"正确答案是 20°"，而是说"20° 最可能，18°、22° 也有点可能"，训练更稳 | 每 2° 一类，σ = 4° |

- 打个比方：训练集是课本和练习题，验证集是模拟考（用来决定复习到哪一版），测试集是正式考试（只考一次）。

## 七a、我们在做什么、那些数字是什么意思（11-25 补充）

**一句话**：摄像头上的 6 个麦克风听到同一个声音会有极微小的先后差别，小网络从这些差别判断"声音从哪个方向来"，摄像头据此转过去。

| 词 | 一句话 | 我们这里 |
|---|---|---|
| **准确率（误差 ≤10° 的比例）** | 考 100 题，有多少题方向猜得足够准（误差不超过 10°） | "96%" = 100 题里 96 题够准 |
| **仿真数据** | 电脑在虚拟房间里算出麦克风会听到什么，可以大量生成 | 训练用 1.2 万 / 6 万条 |
| **真实录音（实录）** | 真房间里真麦克风录的（RealMAN 公开数据） | 最终要看的"实际考试" |
| **训练集 / 验证集 / 测试集** | 课本练习 / 模拟考（挑版本、定参数）/ 正式考试（只考一次） | 仿真验证集 1,000 条；实录测试 600 条 |
| **种子（seed）** | 训练的随机起点编号；换种子结果会差一点（运气） | 每组跑两个种子，差距要明显大于这个波动才算数 |
| **s 档 / l 档** | 小模型（0.28 M 参数，竞品量级，能放进设备）/ 放大约 8 倍的大模型 | 数据够多时 s 追平 l |
| **数据量 vs 训练轮数** | 题多 vs 练得多：6 万条 × 30 轮的练习量是 1.2 万条 × 30 轮的 5 倍 | 对照实验：1.2 万条 × 150 轮，练习量相同，看分数是否也上去 |
| **轮（epoch）** | 把训练集完整做一遍 | 30 轮 / 150 轮 |

- 当前在回答的三个问题：数据多了会不会更准？是"题多"还是"练得多"？仿真上的进步在真实录音上还在不在？
- 分工：服务器负责训练与实录评测（GPU 快）；云端负责写代码、设计实验、分析与记录；结果以文字传回。

## 七b、置信度与量化（11-18 补充）

| 词 | 一句话 | 我们这次 |
|---|---|---|
| **置信度** | 网络对自己答案有多大把握（0–1）；把握低时可以先不转 | 取网络输出概率在峰值 ±6° 内的总和 |
| **AUROC** | 衡量"置信度能不能分开对和错"：随便挑一个对的、一个错的，对的置信度更高的概率；0.5 = 瞎猜，1 = 完全分开 | 0.85 |
| **门限** | 置信度低于某个值就不输出（不转） | 在验证会议上比较 0.6–0.8，选定 0.7 |
| **在测试集上调参** | 用最终评测的数据去挑参数，成绩会偏乐观；参数要在验证数据上挑，测试数据只评一次 | 11-18 门限 0.6 就是这样挑出来的，换一批会议后不成立，11-21 已重做 |
| **量化（8 比特）** | 把网络里的 32 位浮点数换成 8 位整数存和算，模型小 4 倍、芯片上算得快；代价是数字变粗，可能掉准确率 | 模拟 8 比特后准确率不变（95%），权重约 270 KB |
| **W8 / W8A8** | W = 权重（weights），A = 激活（中间结果）；W8A8 表示两者都量化成 8 比特 | 两种都试了 |
| **平衡点（取舍）** | 同一个系统调门限，误转少了，漏转就会多；没有"全面更好"，只能按产品更怕哪种错误来选 | 纯噪声训练后误转少约四成，对准低约 4 个百分点 |
| **置信度刻度会变** | 模型一改，置信度的数值含义就变了，旧门限不能直接沿用，要在验证数据上重新定 | 新模型门限按验证集换算为 0.53 |
| **深度可分离卷积** | 把一个普通卷积拆成"逐通道"+"1×1 混合"两步，计算量能降几倍，常用于端侧网络 | 估算可把 2.7 亿降到约 0.8 亿（需重新训练验证） |

## 七c、实录微调与"要采多少数据"（11-27 补充）

| 词 | 一句话 | 我们这次 |
|---|---|---|
| **仿真与真实的差距（sim-to-real gap）** | 仿真房间再像，也和真房间有差别（扩散声、麦克风误差、真实噪声）；仿真上学得再好，到真实录音上会打折 | 仿真 97%，真实录音约 80%；加仿真数据、放大网络都不变 |
| **微调（fine-tune）** | 在已经训练好的模型上，用少量新数据再练一会儿，学习率小一些，不从头训练 | 用 RealMAN 另外 3 个房间的真实录音微调：81% → 87% |
| **混合训练** | 微调时每批一半真实录音、一半仿真数据，防止只记住那几个房间、忘了仿真里学到的情况 | 一直这样做 |
| **合成样本** | 把两段单人录音相加，就得到"换人""抢话"的样本，不必真的让两个人按各种组合说话 | 采集时只需每个位置录单人说话 + 无人说话的背景声 |
| **数据量曲线** | 用 1/8、1/4、1/2、全部的数据各练一次，看效果随数据量怎么变；曲线变平的地方就是"够用了" | 用来回答"自己阵列要录多少分钟" |
| **控制变量** | 比较两个条件时，除了要比的那一项，其他都相同 | 各组训练步数相同、样本总数都是 4,500，只改用了多少录音 / 几个房间 |
| **按房间分训练和测试** | 测试用的房间不能出现在训练里，否则成绩偏乐观（模型可能记住了房间） | 微调 3 个房间、挑选 1 个房间、测试 5 个房间，互不重叠 |
| **事先定判断规则** | 看结果之前写好"什么结果说明什么"，避免看到结果再找理由 | 每个实验的规则都写在计划文件里 |

## 七、开会时的小技巧

- 开会前把要问的问题写下来（每次 3–4 个）。
- 开会时录音转写（像 11-16 这样），会后把转写发给 Claude 整理纪要，并补充这份笔记。
- 听不懂可以当场问一句："您说的 X 是指……吗？"——复述一遍比事后猜更可靠。
- 会后 5 分钟写三行：**定了什么 / 要我做什么 / 我还没懂什么**。
