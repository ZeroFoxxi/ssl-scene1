# mentor 11-23 两种情况的定位仿真【仿真】

> 2026-11-23。代码：`code/earbud_ssl/scripts/run_two_cases.py`；结果：`out/two_cases.json`、`out/two_cases_log.txt`。
> 情况 1：面前 3 个人，1 个人在跟你说话，另外 2 个不说话。情况 2：另外 2 个人在互相说话。

## 1. 结论

1. **情况 1：靠声音为主就够**【仿真】。只用声音 90.5%，加低帧率摄像头的人脸位置 96.0%，再加唇动 100%。只用声音时的错误主要来自对方开口没被及时检出（开口后 0.3 s 内只检出 65.5%，但没有误检）；检出时几乎全对。情况 1 没有干扰，开口检测阈值可以比多人场景调低，或由低帧率档的人脸位置补上。
2. **情况 2：需要唇动（高帧率档）**【仿真】。另外两人与目标一样响时，只用声音 60.0%，加人脸位置 63.0%，加唇动 88.0%；没有唇动时约三分之一会锁到另外两人身上（34.5–36.0%），加唇动后降到 11.5%。另外两人低 6 dB 时分别为 78.5%、82.0%、91.0%。
3. **只看唇动不够**：情况 2 中另外两人也在说话、嘴也在动，只看唇动约一半会选错人（48.5–51.0%）；要声音与画面一起判断。
4. **摄像头怎么开**【判断】：情况 1 只开低帧率档即可；情况 2 对话中要开高帧率档。与 `摄像头使用策略.md` 的结论一致，并把适用场景分清了。
5. 定位找准之后，情况 2 还要靠增强把另外两人压下去，这取决于左右耳机之间能否几毫秒内互传声音（第 11 页关键风险），不在本仿真内。

## 2. 设置

| 项目 | 设置 |
|---|---|
| 人 | 3 人都在正前方：中间一人在 ±30° 内，相邻两人隔 20–30°，距离 1–2 m；目标是 3 人中随机一个 |
| 目标说话 | 3 s 片段，第 2.0 s 开口（目标语音的第一个有声帧对齐开口时刻），开口后 0.5 s 判决 |
| 情况 2 的另外两人 | 从片段开始就在互相说：两人轮流，每次 1.5–4 s，换人间隔 0.1–0.5 s；与目标一样响或低 6 dB |
| 房间 | 混响 RT60 0.5 s，扩散噪声 SNR 10 dB；刚性球头部，阵列 2+1 |
| 视觉（假设） | 3 张脸都在视野内，检出 95%、方位误差 2°；在说话的人唇动分数高，10% 判反 |
| 方法 | 不开摄像头：声学检测开口（新声源能量 3.5 dB）→ GEVD-MUSIC，没检出时用最近 0.5 s 的 MUSIC；低帧率档：同上再与人脸位置软融合；高帧率档：唇动给开口时刻（±0.1 s 误差）→ GEVD-MUSIC，与人脸 + 唇动软融合；仅视觉：唇动最高的人脸 |
| 次数 | 每种条件 200 次（比例的统计误差约 ±3–7 个百分点） |

## 3. 结果

方位误差 ≤ 10° 的比例 / 锁到另外两人之一的比例：

| 方法 | 情况 1 | 情况 2：另外两人低 6 dB | 情况 2：一样响 |
|---|---|---|---|
| 不开摄像头（只用声音） | 90.5% / 0% | 78.5% / 14.0% | 60.0% / 34.5% |
| 低帧率档（声音 + 人脸位置） | 96.0% / 0% | 82.0% / 15.5% | 63.0% / 36.0% |
| 高帧率档（声音 + 人脸 + 唇动） | 100% / 0% | 91.0% / 9.0% | 88.0% / 11.5% |
| 仅视觉（唇动最高） | 81.5% / 18.5% | 48.5% / 51.5% | 51.0% / 49.0% |

声学开口检测（新声源能量 3.5 dB）：开口后 0.3 s 内检出 65.5% / 41.0% / 26.0%；开口前 1 s 内平均误检 0 / 0.06 / 0.08 次。

## 4. 局限

- 刚性球头部、视觉按假设模拟（同其他仿真）。
- 一次性判决（开口后 0.5 s），没有跟踪与说话人地图；连续对话中已在地图里的人再开口时会更快、更准（`摄像头使用策略.md`）。
- 另外两人的轮流方式是随机生成的；真实对话中两人的重叠更多时会更难。
- 情况 1 的开口检测阈值沿用了多人场景的 3.5 dB，未专门调。
