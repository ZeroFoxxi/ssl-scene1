# 耳机声源定位 demo：无障碍听觉辅助

> 新会话做耳机相关工作时先读本文件。更新日期：2026-11-18。
> 内容分三类：**查到的事实**、**仿真结果**、**判断**（判断会标明）。mentor 要求的原话整理见 `记录/mentor沟通/2026-11-18_耳机demo要求纪要.md`。

## 1. 任务与目标（mentor 11-17、11-18 明确）

- **场景**：无障碍听觉辅助。锁定视野中的说话人并增强其语音，帮听力损失人群和嘈杂环境中的普通用户听清对话（mentor 的技术洞察 PPT，见 `资料/`）。
- **技术方案**：耳机端声源定位算法 + 摄像头端人脸检测、唇动检测，做音视频融合，提高目标说话人定位的准确性。
  - **耳机声源定位是主体，摄像头是辅助。**
  - **先假定说话人位置固定**；之后再加说话人移动时的动态定位与持续跟踪。
- **分工**：我们只负责**声源定位算法**。人脸检测、唇动检测由 mentor 找视觉同事负责。
- **约束**：整体都是**端侧、离线**（11-16："声源定位我们也是做端侧的"；端侧低功耗是重点；翻译例子里离线是为了保护隐私）。耳机功耗很低，定位算法要**极低算力**；和场景一（摄像头确定说话人并持续跟踪）的定位模型**不是同一个**。
- **怎么做由我们决定**：mentor 给了场景、主次、分工和时间；硬件假设、pipeline、融合方式、算法选型都需要我们探索后提出（第 7 节）。
- **顺序**：先把整个技术方案的 pipeline 定下来（输入怎么传进耳机、耳机怎么输出信号、音频与视觉怎么协同和融合），**再**确定里面用哪个声源定位算法。
- **时间节点**：
  - **11 月底**：完成"整体技术方案，明确音频与视觉算法的协同机制及融合流程"和具体算法选型。
  - **12 月**：出仿真效果。
  - 要快：这个点子其他公司也可能想到。

## 2. 本月交付物要回答的问题（判断，按 mentor 要求拆解）

技术方案文档按下面七块写，每块都要落到"输入是什么、在哪里算、输出给谁"：

1. **系统框图与数据流**：麦克风 / IMU / 摄像头 → 各算法模块 → 输出；每个模块跑在哪个端侧单元上（耳机主芯片、摄像头模组 NPU 等），不依赖云端。
2. **输入**：每只耳机的麦克风数量、间距、采样率；两耳之间传音频还是只传参数；摄像头的数量、朝向、视场角、帧率；视觉结果以什么形式传给耳机（倾向只传"人脸方位、唇动状态、置信度、时间戳"，不传视频）。
3. **协同机制**：摄像头常开还是按需开；声学与视觉的坐标统一（摄像头与麦克风的相对位置、IMU 头动补偿）；时间对齐。
4. **融合流程**：声学候选方向（含前后镜像）与视觉人脸方位怎么匹配；唇动怎么门控；视觉缺失、目标在视野外、光线差时怎么降级到纯声学。
5. **输出**：目标方位 + 置信度给语音增强模块；增强后的语音怎么送进双耳（单路，还是保留双耳方向线索）；端到端时延预算。
6. **算法选型**：候选声源定位方法、算力量级、选择理由。
7. **12 月仿真计划**：仿真什么、用什么指标、对比哪几组（纯声学 vs 音视频融合）。

## 4. 已知技术难点（初步，判断）

- **两耳同步**：两耳最大时间差约 0.5–0.7 ms；正前方附近每 1° 只对应约 10 µs 的时间差（按 18 cm 基线、声速 343 m/s 估算）。两耳之间如果走无线、采样时钟不同步，跨耳测向需要微秒级同步。这直接决定"两耳传音频组阵"还是"每只耳机各自测向、只传参数"。
- **前后镜像**：两耳左右对称，正前方和正后方的声学线索几乎一样。视觉能直接消除；纯声学可以借助转头时时间差的变化趋势。
- **佩戴者自己说话**：嘴离麦克风很近，会压过对方的声音；需要骨导 / VPU 判断自语音并屏蔽。
- **头动补偿**：说话人不动、头在动时，相对方向一直在变，要用 IMU 换算到世界坐标。
- **视觉与声学对齐**：摄像头装在耳柄上，两者的相对位置和时间戳要标定。
- **时延**：实时听的链路时延过大，会和对方的口型、透过耳塞漏进来的原声对不上。

## 5. 对技术洞察 PPT 的几处核查（判断，供修改参考）

1. 第 4、5 页"前后**镇**像"应为"前后**镜**像"。
2. 第 6 页"单耳麦克风间距仅几毫米"：常见 TWS 耳柄上的双麦间距更接近 1–2 cm【待核实具体机型】；"对 3 米外目标说话人基本没有测向能力"说得偏重，单耳前后两麦至少能给出前后方向的线索。
3. 第 7 页"音视频融合方案还是一片空白"：此前检索报告里已有相关专利和产品——Google US11792597B2（眼镜按注视方向引导波束）、Samsung US12482469B2（口型匹配后把麦克风指向对方）、OrCam（用唇动选择放大的语音）——尚未逐一复核原文。建议改为"耳机形态尚无成熟产品"。
4. 第 5 页"直接播放单路语音"：单路输出会丢失方向感。方案里要定下来是单路还是保留双耳线索；这也是以后接音效渲染的接口。
