# 耳间转发的 1 路音频怎么编码：对测向的影响【仿真】

> 2026-11-23。回答方案中待验证的一项："副耳转发给主耳的 1 路音频能否用 ADPCM 压缩、LC3 这类感知编码能否用于定位"。
> 代码：`code/earbud_ssl/scripts/run_codec.py`；结果：`out/codec.json`（汇总）、`out/codec_trials.json`（逐段）。

## 1. 结论

1. **IMA ADPCM 4 bit（64 kbps）可以用**【仿真】：加视觉时与 PCM 没有差别（94.5% 对 94.0%，79.5% 对 79.0%），逐段配对时 93–99.5% 的段估计方位与 PCM 相差不到 2°。纯声学、干扰与目标一样响时低 3 个百分点（60.5% 对 63.5%），配对检验不显著（p = 0.11）。
2. **改用 ADPCM 每只耳机约省 1.9 mW**（耳间定位音频 2.6 → 0.7 mW【估算】），续航多约 0.2 h。
3. **感知编码（用 Opus 32 kbps 代替 LC3 测试）不适合定位**【仿真】：加视觉时低 3–7.5 个百分点（91.0% 对 94.0%，71.5% 对 79.0%），纯声学时低 6.5–10.5 个百分点，配对检验显著（干扰一样响时 p ≤ 0.008）。
4. **G.722（64 kbps，子带 ADPCM）介于两者之间**：低 2–2.5 个百分点，不显著；与 IMA ADPCM 码率相同、没有优势。
5. **建议**【判断】：定位转发默认用 ADPCM 4 bit；暗光等只能靠纯声学的情况可以切回 PCM（损失本来就不显著，是否需要切换在 12 月用实测头部传递函数复核）；感知编码不用于定位。

## 2. 设置

| 项目 | 设置 |
|---|---|
| 场景 | 与算法选型 S2、S4 相同：混响 RT60 0.5 s、2 个干扰说话人（各低 6 dB / 与目标一样响）、扩散噪声 SNR 10 dB；目标在前方 ±60°、1–2 m；每个条件 200 段，各编码用同一批场景 |
| 阵列 | 2+1：主耳 2 路 + 副耳转发 1 路（右前麦） |
| 信号链 | STFT 域仿真 → 逆变换回时域 → 三路统一按 16 bit 量化（副耳那一路均方根 −30 dBFS）→ 只对副耳那一路编码再解码 → 测向 |
| 编码（ffmpeg） | PCM 16 bit（参照）；IMA ADPCM 4 bit；G.722 64 kbps；Opus 32 kbps（10 ms 帧，代替 LC3） |
| 编码时延 | 白噪声探测后按整数样点补偿（G.722 22 个样点，其余 0），实际系统中该时延已知 |
| 测向 | GEVD-MUSIC（唇动门控背景，起始段加权，5° 网格），开口后 0.5 s 判决；加视觉为软融合（λ = 0.1、μ = 0.05、±8°），视觉按假设模拟 |

PCM 参照（94.0% / 79.0%）与麦克风数量仿真中 2+1 的结果（96% / 80%，100 段）一致，说明逆变换和 16 bit 量化本身不引入损失。

## 3. 结果（方位误差 ≤ 10° 的比例，200 段）

| 编码 | 码率 | 编码误差信噪比（中位数） | 干扰低 6 dB：纯声学 / 加视觉 | 干扰一样响：纯声学 / 加视觉 |
|---|---|---|---|---|
| PCM 16 bit | 256 kbps | 53 dB | 87.0% / 94.0% | 63.5% / 79.0% |
| IMA ADPCM 4 bit | 64 kbps | 25 dB | 87.0% / 94.5% | 60.5% / 79.5% |
| G.722 | 64 kbps | 26 dB | 85.0% / 92.0% | 61.0% / 76.5% |
| Opus（代替 LC3） | 32 kbps | 15 dB | 80.5% / 91.0% | 53.0% / 71.5% |

与 PCM 逐段配对（同一段场景，对 → 错 / 错 → 对 的段数，符号检验 p 值）：

| 编码 | 干扰低 6 dB：纯声学 | 加视觉 | 干扰一样响：纯声学 | 加视觉 |
|---|---|---|---|---|
| IMA ADPCM | 1 / 1（p = 1） | 0 / 1 | 8 / 2（p = 0.11） | 5 / 6（p = 1） |
| G.722 | 5 / 1（p = 0.22） | 4 / 0（p = 0.13） | 8 / 3（p = 0.23） | 8 / 3（p = 0.23） |
| Opus | 15 / 2（p = 0.002） | 8 / 2（p = 0.11） | 29 / 8（p = 0.001） | 22 / 7（p = 0.008） |

## 4. 局限

- LC3 在当前环境无法安装，用同为感知编码的 Opus 代替；两者算法不同，LC3 的实际影响需要用 LC3 复核【待确认】。
- 刚性球头部模型；编码误差对相位的影响在实测头部传递函数下可能不同，12 月复核（`12月仿真计划.md`）。
- 只编码了副耳那一路；两耳链路的丢包、重传未建模。
